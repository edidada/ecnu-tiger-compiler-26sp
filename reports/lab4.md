# ECNU Tiger 26sp Lab4：语义分析与类型检查

## 来源与实现

上游为 https://gitee.com/east-china-normal-university_ttb_cs/tiger-compiler-26sp 的 lab4 分支，起点 bf1ae63a3ce3caf48ffebf6c1f1bff0ac369ad92。工作分支 edidada/lab4。作为 ECNU 补充课程记录，不替代 SJTU 当前课程受限材料。

实现 AST 的全部语义接口，含变量、字段、下标、调用、运算、记录/数组构造、顺序表达式、赋值、条件、循环、let、声明和类型。函数组先安装完整签名，再在独立作用域中检查所有函数体，支持互递归。函数体从零开始计算循环深度，禁止通过嵌套函数 break 外层函数的循环；for 索引只在循环体可见且只读，允许内层新变量合法遮蔽。

类型组先安装占位别名，再解析引用。纯别名环显式诊断并打断，记录或数组边界允许递归。类型实际化采用迭代加访问集，未解析引用或非法环恢复为 Void，避免递归栈溢出或空指针。数组和记录保持名义同一性，nil 只与具体记录兼容；条件分支 nil/record 合并保留记录类型。新增标准 not(int):int 基础函数。诊断后继续检查其余独立节点，部分非法类型可能产生额外恢复诊断。

继承本地 Lab2/3 的实际扫描器和完整 parser，包括位置栈及驻留符号非节点所有权修正。本实验不宣称已有前置实验 CI 通过。

## 远端验证设计

独立 .github/workflows/lab4.yml 在 Ubuntu 24.04 安装 flexc++/bisonc++，通过 scripts/verify_lab4.py 按 Release 构建。全部 52 个上游输入保留原文件；正常样例必须无输出、正常退出，负例按参考诊断文本逐项检查数量，不把恢复产生的其他诊断隐藏，JSON 同时保留 actual 与 extra。原 grader 仅筛选诊断文本，因此这里不以错误坐标相同为验收条件。语法错误 test49 必须失败退出，其余原驱动的语义错误仍遵循原来的零退出码行为。

另有 22 个完整 Tiger 程序，严格比对诊断文本的多重集及新增驱动的退出码，覆盖互递归、递归记录、别名/名义类型、nil 分支、变量遮蔽、跨函数 break、只读索引、作用域泄漏、缺少参数、重复字段/参数及过程返回值。独立 C++ 检查别名实际化、环恢复、类型同一性和嵌套作用域恢复。每个执行限制十秒，总工作流十五分钟；上传输出与汇总 JSON。

## 上游缺失参考输出

上游 test50.tig 有循环结束后的 break，却缺少 test50.out。原始文件和缺失状态均保留，不能将缺失参考输出视为通过。本验证对它单独要求循环外 break 诊断。语言依据：[Tiger Language Reference Manual 2.8](https://bcmi.sjtu.edu.cn/home/limu/tiger/Res/tiger.pdf)，break 只可终止同一函数内包围它的循环。该项明确标记为语言规则补充，并非伪造上游答案。
